# ArchMind 用户画像与使用场景

> 版本 v1.0 ｜ 2026-09-08 ｜ 来源于产品一页纸与 PRD 的既有定义，不虚构未验证数据

## 一、目标用户（优先级分层）

| 优先级 | 用户 | 核心诉求 | 典型痛点 |
|---|---|---|---|
| P0 | 建筑学研究生 | 写论文、做课程汇报、读文献 | 规范条文关联性强、文献查阅耗时长 |
| P1 | 设计师助理 | 日常设计查规范、出方案 | 查一条规范平均 8.6 分钟、怕查错版本 |
| P2 | 建筑从业者 | 复核规范、准备汇报材料 | 规范多而杂、废止标准混杂难判断 |

## 二、高频使用场景（v2.0 沉淀的 4 类）

| 场景 | 用户动作 | 期望产出 |
|---|---|---|
| 课程汇报 | 上传案例资料 → 生成汇报 | 结构化报告 + 汇报提纲 |
| 论文分析 | 上传文献/规范 → 分析 | 分维度分析 + 来源标注 |
| 作品集图注 | 上传方案图纸/说明 | 图注文案 + 设计策略提炼 |
| 设计策略 | 上传项目资料 → 问策略 | 设计策略清单 + 依据出处 |

## 三、核心使用路径

1. 上传资料（规范 TXT/PDF、文献、案例）
2. 用自然语言提问，获取带来源片段的回答（v1.0 已实现）
3. 选择用途与维度，生成场景化分析报告（v2.0 规划中）
4. 导出报告 / 保存到我的案例库（v2.0 规划中）

## 四、使用边界

- 回答基于用户已上传的资料，不保证覆盖全部现行规范
- 用于个人学习研究；涉及合规决策时需人工核对原文
